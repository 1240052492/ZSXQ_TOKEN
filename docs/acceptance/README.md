# 验收矩阵使用规范

`matrix.json` 是合并门禁的机器可读事实源，模块详细说明见仓库根目录的 `ZSXQ_整合项目_模块验收目标.md`。

## Pull Request 更新规则

- 代码、配置、迁移或部署变更必须关联一个或多个 `Mxx` 或 `Exx` 验收编号。
- `planned`、`in_progress` 和 `blocked` 不能作为生产放行证据。
- 只有同时具备 `status=passed`、非空 `evidence` 和 `verified_by` 的条目才会被 CI 视为通过。
- P0/P1 条目必须通过；P2 条目可在有批准的延期记录时保留未通过状态。
- 证据链接必须指向测试报告、日志、数据库查询结果、截图或审计记录，不接受“代码已实现”作为唯一证据。

## 合并门禁分层

- `Acceptance Gate`：结构、追踪、状态、P0/P1 和证据完整性。
- `Security Gate`：阻止明显的密钥/密码/授权码泄露和不合规的生产状态声明。
