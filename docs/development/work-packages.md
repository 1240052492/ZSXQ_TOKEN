# ZSXQ_TOKEN 开发工作包

本文档把 New API + LocalMiniDrama 整合方案拆成可排期、可分工、可合并的开发工作包。工作包不是“功能愿望清单”，每个包必须产出代码/配置/迁移/测试/证据，并通过现有验收门禁后才能关闭。

当前基线：仓库已完成验收矩阵和 GitHub 合并门禁；New API、LocalMiniDrama 业务源码尚未进入本仓库，因此 `WP-00` 是所有实现工作的前置包。

## 1. 工作包状态与关闭规则

- `planned`：已定义，尚未开始。
- `in_progress`：已产生实现或测试提交。
- `blocked`：存在明确外部阻塞，必须记录原因、责任人和解除条件。
- `done`：代码、测试、文档、证据和验收项均通过。

一个工作包只有同时满足以下条件才能标记为 `done`：

1. 代码、配置或迁移已通过 Pull Request 合并。
2. 单元、集成和失败路径测试达到该包要求。
3. `docs/acceptance/matrix.json` 中关联项有真实证据链接，不能只写“已实现”。
4. 无未关闭的 P0/P1 缺陷。
5. 运行手册、回滚方式和安全影响已更新。

          ├─> WP-09 素材存储与导出
          └─> WP-10 个人空间、只读分享与内容治理

WP-09 和 WP-10 可以在 WP-07 的基础适配完成后并行；WP-11、WP-12 不得在核心账务和代理链路通过前提前宣称完成。

## 3. 可执行工作包

### WP-00 源码、许可证与兼容性审计

**目标**：确认两个上游项目的真实技术边界，冻结后续实现依据。

**前置依赖**：无。

**实施任务**：

- 固定 `QuantumNous/new-api` 和 `1240052492/LocalMiniDrama` 的 commit、分支和下载来源。
- 盘点后端、前端、数据库、迁移、队列、对象存储、认证、支付、模型渠道和任务状态实现。
- 识别 LocalMiniDrama 中必须删除、替换或隔离的本地账号、钱包、供应商密钥和直连路径。
- 生成第三方依赖、许可证声明、SBOM 和来源影响清单；本仓库不设人工许可证审查门禁。
- 输出接口差异表、数据迁移风险表和不可复用代码清单。

**交付物**：`source-baseline.md`、commit 清单、许可证声明清单、整合 ADR、风险登记表、[WP-00 测试计划](./wp-00-test-plan.md)及其执行报告。

**验收/测试**：M01；能够从固定 commit 重建两个上游制品，保留上游许可证和版权声明文件。

**完成定义**：审计报告经平台负责人和合规负责人确认，后续工作包引用的版本不再漂移。

### WP-01 派生仓、构建与开发环境基线

**目标**：建立可重复构建、可审查、可回滚的代码拓扑。

**前置依赖**：WP-00。

**实施任务**：

- 建立 LocalMiniDrama 独立私有派生仓或固定子模块；保留上游同步记录。
- 为 `new-api`、`opc_core`、`super_canvas` 定义服务目录、环境变量模板和本地启动方式。
- 固定 Node/Go/Python/数据库/队列等运行时版本，以 WP-00 的真实技术栈为准。
- 增加构建、单元测试、迁移检查、许可证检查和安全扫描工作流。
- 为每个服务生成不可变构建制品和版本清单。

**交付物**：仓库拓扑、开发容器/启动脚本、CI 工作流、版本锁定文件、构建说明。

**验收/测试**：M01、M20；干净环境可重复构建；构建制品可按 commit 回滚。

**完成定义**：新开发者可按文档启动依赖服务并通过基础 smoke test。

### WP-02 三库三账号与跨服务契约

**目标**：落地 `new_api`、`opc_core`、`super_canvas` 分库、分账号、分迁移，不共享业务表。

**前置依赖**：WP-00、WP-01。

**实施任务**：

- 建立三个 PostgreSQL 数据库、owner、runtime 账号和 migration 账号。
- 定义用户、业务事件、模型、报价、预扣、任务、素材和审计 ID 的跨服务标识规则。
- 建立服务间认证、请求签名、超时、重试和幂等头约定。
- 为 `opc_core` 实现服务注册、事件接收、策略/版本引用和跨服务审计索引；不得保存钱包余额。
- 增加数据库权限拒绝测试和禁止跨库业务外键检查。

**交付物**：三库初始化迁移、权限矩阵、OpenAPI/事件契约、服务认证配置。

**验收/测试**：M05、M20；画布账号无法读写钱包表；三库可独立迁移、备份和恢复。

**完成定义**：所有后续工作包只能通过契约/API 访问其他服务，不允许新增跨库 SQL。

### WP-03 New API 统一身份与一次性 SSO

**目标**：用户只在 New API 注册/登录，并通过授权码进入画布。

**前置依赖**：WP-02。

**实施任务**：

- 增加面向 `canvas` audience 的一次性授权码签发和兑换接口。
- 授权码包含短过期时间、随机 state、单次消费标识和环境/服务约束。
- 画布后端兑换授权码后建立本地会话，只保存 New API 用户 ID 映射。
- 实现过期、重放、错误 audience、错误 state、并发兑换和登出失效处理。
- 不共享跨子域 Cookie，不把长期 token 放入 URL 或前端源码。

**交付物**：SSO API、画布回调、会话映射表、认证时序图和安全测试。

**验收/测试**：M03、M04、M19、E2E-01；正常跳转和新标签页免登录通过，所有重放测试拒绝。

**完成定义**：画布删除本地注册/密码路径，账号禁用后无法创建新任务。

### WP-04 New API 钱包、充值与账务状态机

**目标**：把充值、余额、业务预扣、实际结算和退款统一收敛到 New API。

**前置依赖**：WP-02。

**实施任务**：

- 盘点并适配 New API 现有充值、额度和支付回调模型；不要并行创建第二个钱包。
- 建立不可变账务流水、充值订单、业务来源、任务和请求关联字段。
- 实现支付回调幂等、乱序回调、订单超时、对账和人工冲正审计。
- 实现 `quote`、`reserve`、`settle`、`release/refund` 接口，明确余额锁定和并发语义。
- 以 reservation/task/node 幂等键防止重复扣款、重复结算和重复退款。

**交付物**：账务迁移、钱包 API、支付回调适配、账务对账脚本、异常处理手册。

**验收/测试**：M06、M07、M13、E2E-02；并发和重试下余额可对账，失败任务按规则退款。

**完成定义**：画布和其他业务服务没有余额写权限，只提交业务事件和结算请求。

### WP-05 模型目录、能力标签与价格版本

**目标**：由 New API 提供可计费、可调用、可展示的模型主数据和价格版本。

**前置依赖**：WP-02、WP-04。

**实施任务**：

- 扩展模型主数据：平台模型别名、`enabled`、`canvas_enabled`、能力标签、协议适配器和参数档位。
- 定义文本、图像、视频、语音、音乐、理解/审核六类能力及参数校验。
- 为平台模型配置多渠道、渠道健康、协议兼容和同模型约束。
- 实现价格草稿、发布、停用和版本查询；报价返回价格版本和计费单位。
- 任务创建时保存模型别名、能力、参数、报价、价格版本和候选渠道快照。

**交付物**：模型/能力/渠道迁移、目录 API、报价 API、后台配置页面、价格版本审计。

**验收/测试**：M08、M09、M10、E2E-03、E2E-04；草稿不可报价，改价不影响历史任务，过滤条件不可绕过。

**完成定义**：画布不自行维护模型价格和可用性判断，所有展示与调用均以 New API 结果为准。

### WP-06 New API 受控模型代理与渠道容灾

**目标**：让画布通过统一代理调用模型，隐藏供应商密钥并实现同平台模型容灾。

**前置依赖**：WP-04、WP-05。

**实施任务**：

- 实现代理请求鉴权：用户、任务、能力、价格版本、reservation 和服务权限。
- 将渠道选择限制在同一 `platform_model_id`、协议和价格规则范围内。
- 实现健康检查、超时、有限重试、错误映射和实际用量上报。
- 禁止自动换成不同模型或不同价格；无合规渠道时明确失败并释放/退款。
- 记录请求、响应摘要、实际渠道、用量、错误和任务 ID，禁止记录密钥和完整提示词（按隐私策略）。

**交付物**：代理 API、渠道适配器、健康检查、错误码、用量上报和密钥隔离配置。

**验收/测试**：M09、M11、M19、E2E-03；供应商直连和静默换模测试失败即阻断。

**完成定义**：浏览器和画布服务均无法获得供应商密钥，所有模型调用能关联账务预扣。

### WP-07 LocalMiniDrama 画布适配层

**目标**：保留画布编辑器和工作流体验，替换身份、模型、计费和任务后端。

**前置依赖**：WP-01、WP-02、WP-03、WP-05、WP-06。

**实施任务**：

- 将 LocalMiniDrama 固定版本接入派生仓，保留上游同步点和局部修改记录。
- 删除/隔离画布本地注册、钱包、供应商密钥和直连调用路径。
- 增加 SSO 回调、用户映射、模型目录适配和报价/预扣/代理客户端。
- 将节点参数转换为平台能力和参数档位，拒绝不支持协议的节点。
- 保存任务快照、价格版本、实际渠道和素材引用。

**交付物**：画布适配层、节点协议映射、前后端配置、回归测试和迁移说明。

**验收/测试**：M12、E2E-01；文本、图像、视频等代表性节点完成真实 sandbox 调用。

**完成定义**：用户能从统一登录进入画布并创建任务，但画布不拥有扣款和供应商访问权。

### WP-08 任务状态、幂等、重试与恢复

**目标**：让工作流任务在重复请求、超时、取消和 worker 重启后保持一致。

**前置依赖**：WP-04、WP-06、WP-07。

**实施任务**：

- 固化任务/节点状态：`created`、`reserved`、`queued`、`running`、`succeeded`、`failed`、`cancelled`、`refunded`。
- 为创建、回调、取消、结算、退款和重试定义幂等键及唯一约束。
- 实现 worker 重启恢复、超时扫描、死信/人工处理和补偿任务。
- 对多节点工作流按节点结算，成功节点不被失败节点错误冲销。
- 记录状态迁移、错误原因、重试次数和补偿来源。

**交付物**：状态机、队列消费者、幂等存储、恢复脚本和故障注入测试。

**验收/测试**：M07、M13、E2E-02；重复请求和重启演练不重复执行、不重复扣款。

**完成定义**：任意任务都能从任务 ID 查询最终状态、资金状态和补偿记录。

### WP-09 素材存储、生命周期与 ZIP 导出

**目标**：首期支持本地存储，同时为正式对象存储和 CDN 预留可替换接口。

**前置依赖**：WP-02、WP-07、WP-08。

**实施任务**：

- 建立素材元数据、对象 key、用户/项目归属、大小、哈希、保留期和删除状态。
- 实现本地 provider、容量限制、签名 URL、延迟清理和孤儿对象扫描。
- 定义 COS/OSS/S3/MinIO provider 接口和管理员配置模型；不向用户暴露密钥。
- 实现异步 ZIP 导出、权限校验、路径安全、进度、失败重试和过期清理。
- 预留 CDN 回源、缓存失效和删除传播接口；正式上线前再切换。

**交付物**：storage provider 接口、本地实现、生命周期 worker、ZIP worker、管理员配置和迁移脚本。

**验收/测试**：M14、M15、M16、E2E-05；超容量、到期清理、越权导出、删除后访问和缓存失效通过。

**完成定义**：存储 provider 可替换且不改变画布任务和素材业务接口。

### WP-10 个人空间、只读分享与内容治理

**目标**：实现个人空间、只读分享、内容审核、违规处置和用户协议。

**前置依赖**：WP-03、WP-07、WP-09。

**实施任务**：

- 实现个人项目/素材权限，只允许所有者管理。
- 实现短期、可撤销、可限流的只读分享；禁止编辑、执行任务、复制和共享钱包。
- 在提示词、上传素材、任务输入、生成结果和分享前接入审核状态机。
- 实现拒绝、隔离、删除、申诉/人工处理记录及违规审计。
- 记录用户协议版本和首次使用确认；协议更新可要求重新确认。

**交付物**：分享授权、审核接口/队列、违规处理、协议版本表、审计查询和运营手册。

**验收/测试**：M17、M18、M19、E2E-05；分享撤销、项目删除和审核拒绝立即阻断后续访问并按规则退款。

**完成定义**：不存在团队协作、共享钱包或审核绕过路径。

### WP-11 端到端、支付、容灾与安全演练

**目标**：证明核心链路在真实失败条件下仍满足验收规则。

**前置依赖**：WP-03 至 WP-10 的相关功能包。

**实施任务**：

- 编写 E2E-01 正常任务闭环测试。
- 注入调用前失败、上游错误、超时、取消、审核失败和 worker 重启，完成 E2E-02。
- 注入主渠道故障、价格不一致、所有渠道不可用，完成 E2E-03。
- 在任务运行中发布新价格，完成 E2E-04。
- 验证分享、审核、删除、签名 URL 和 CDN/对象清理，完成 E2E-05。
- 执行支付回调幂等、余额并发、越权、重放、密钥扫描和日志脱敏测试。

**交付物**：自动化 E2E、故障注入脚本、测试报告、缺陷清单和证据附件。

**验收/测试**：E2E-01 至 E2E-05；M06、M07、M09、M13、M18、M19 全部 P0/P1 通过。

**完成定义**：所有资金、权限、静默换模和数据泄露风险均有通过证据或明确阻断记录。

### WP-12 可观测性、备份恢复、发布与生产放行

**目标**：建立可追踪、可恢复、可回滚的生产运行能力。

**前置依赖**：WP-01、WP-02、WP-04、WP-08、WP-09、WP-11。

**实施任务**：

- 统一 request/task/reservation/ledger/material/audit ID 的日志和链路字段。
- 建立 SSO、报价、预扣、代理、结算、退款、审核、分享和清理指标与告警。
- 为三库、配置、素材元数据和对象存储制定备份、保留和恢复目标。
- 演练迁移失败回滚、服务回滚、账务恢复、素材恢复和 CDN 缓存失效。
- 生产上线前切换 COS/OSS/S3/MinIO/CDN，完成公网 DNS/HTTPS、容量、延迟和成本验证。
- 完成 AGPL-3.0 专项审查，确认对外服务和源代码提供义务后再开放公网。

**交付物**：监控面板、告警规则、备份恢复手册、发布清单、回滚记录、生产放行签字。

**验收/测试**：M01、M02、M05、M15、M20；G4 生产放行门槛全部通过。

**完成定义**：可以在约定停机窗口内发布/回滚，且恢复后钱包、任务和素材引用一致。

## 4. 推荐排期与并行分工

### Sprint 0：基线冻结

- 主责：平台架构 + 合规。
- 工作包：WP-00、WP-01。
- 退出条件：上游 commit、许可证边界、真实技术栈和本地启动方式确认。

### Sprint 1：平台契约

- 主责：平台后端 + DBA/DevOps。
- 工作包：WP-02。
- 可并行准备：WP-03、WP-04、WP-05 的 API 设计，但不得提前写跨库实现。

### Sprint 2-3：身份、钱包、模型

- 主责：平台后端。
- 工作包：WP-03、WP-04、WP-05。
- 并行条件：三者均只依赖 WP-02；钱包和模型报价接口必须先冻结契约。

### Sprint 3-4：代理与画布适配

- 主责：模型网关 + 画布后端/前端。
- 工作包：WP-06、WP-07。
- 退出条件：至少一种文本和一种图像能力完成 sandbox 闭环。

### Sprint 4-5：可靠性、素材、治理

- 主责：任务平台、存储、内容安全。
- 工作包：WP-08、WP-09、WP-10，可并行开发。

### Sprint 6：集成与放行

- 主责：QA/SRE/合规。
- 工作包：WP-11、WP-12。
- 退出条件：P0/P1 为 0，E2E 全部通过，备份恢复和许可证审查完成。

## 5. Pull Request 拆分规则

- 一个 PR 原则上只关闭一个工作包的一个可审查切片；跨服务变更必须先提交契约 PR。
- PR 标题使用：`[WP-xx] 动词：变更内容`，例如 `[WP-04] feat: add reservation settlement API`。
- PR 描述必须列出：工作包编号、验收编号、数据库迁移、接口变更、测试命令、证据链接和回滚方式。
- 钱包、SSO、模型/价格、权限、迁移、审核和生产配置变更必须由 CODEOWNERS 审批。
- 不允许在同一 PR 同时引入新钱包、新身份系统或未审查的供应商直连。
